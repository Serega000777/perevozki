## ГЛАВНОЕ ПРАВИЛО: записки агентов

Постоянная память проекта — два файла в корне:

- [`AGENT_DONE.md`](AGENT_DONE.md) — что **фактически сделано и проверено** (история и состояние).
- [`AGENT_TODO.md`](AGENT_TODO.md) — **актуальный** план: что делать дальше.

**Перед любой работой их обязательно прочитать. После каждой законченной задачи — обязательно
обновить оба.** Никогда не начинай проект «с нуля», если он уже существует.

## Протокол начала сессии (обязателен)

```text
1. pwd / текущая директория         → должна быть C:\AI\projects\Perevozki (или её клон на VPS/Mac)
2. git status
3. git branch --show-current
4. git remote -v                    → только Serega000777/perevozki
5. прочитать AGENTS.md
6. прочитать AGENT_DONE.md
7. прочитать AGENT_TODO.md
8. git log --oneline -15
9. только после этого продолжать работу
```

Дополнительно проверь `git rev-parse --show-toplevel` — он обязан вернуть корень Perevozki.
**Ловушка этой машины:** в корне диска `C:\` лежит посторонний пустой репозиторий `C:\.git`
(не наш). Если у Perevozki пропадёт свой `.git`, git молча поднимется до `C:\` — тогда стоп,
ничего не коммитить, разобраться. `C:\.git` не трогать и не удалять без команды владельца.

Если код и записки расходятся — проверь код и приведи записки к фактическому состоянию.

## Протокол завершения сессии (обязателен)

```text
1. закончить текущую логическую задачу (или явно остановиться в понятной точке)
2. прогнать доступные проверки (см. «Команды»)
3. обновить AGENT_DONE.md  — только реально сделанное и проверенное
4. обновить AGENT_TODO.md  — выполненное убрать (перенести в DONE), новое добавить
5. git diff                — нет ли лишнего/чужого/секретов
6. git status
7. логичный commit (Conventional Commits: feat:, fix:, chore:, docs:, refactor:, test:)
8. push только в Serega000777/perevozki
```

Незапушенная работа считается несуществующей: другой агент на другой машине её не увидит.

### Правила записок

- В `AGENT_DONE.md` пиши только то, что реально сделано **и проверено**. Частично
  работающее — не `[x]`, а в «Известные проблемы» или в TODO.
- Указывай, какие именно проверки прошли (команда → результат). Не выдумывай.
- Выполненная задача не висит в TODO бесконечно — переносится в DONE.
- Блокеры, которые требуют владельца (токены, DNS, VPS), — в TODO, раздел
  «Требует ручного действия владельца». Остальную работу продолжай.
- В шапке обоих файлов обновляй дату и имя агента: `Claude Code (Windows|Mac|VPS)`,
  `Codex (...)`, `OpenClaw (...)`.

## Запреты и правила безопасности

- **Не работать в соседних проектах** (`C:\AI\projects\*` кроме Perevozki). Не смешивать
  git-историю, ветки, worktree, `.git`, окружения и файлы с другими проектами.
- **Cement CRM — только read-only источник.** Не менять его код, `.env`, БД, Docker, бота,
  не коммитить и не пушить туда, не останавливать его сервисы — без отдельного прямого
  разрешения владельца. Читать и копировать код — можно. Для анализа удобнее свежий клон
  во временной папке, а не локальная папка `C:\AI\projects\crm-cement` (она к тому же
  отстаёт от GitHub, см. AGENT_DONE.md).
- Perevozki не импортирует ничего из Cement CRM: никаких `../cement`, `../../crm-cement`.
  Проект обязан собираться и запускаться, даже если папки Cement CRM нет на диске.
- Перед изменениями — `git status`; перед push — `git remote -v` и `git branch --show-current`.
- **Никакого `git push --force`**, переписывания истории `main`, удаления веток владельца.
- Не удалять рабочие функции. Перенос сначала 1:1, улучшения — отдельными задачами.
- Не менять инфраструктуру VPS и не подключаться к production без отдельного этапа и прямой
  команды владельца.
- **Amola Finance (`amola-finance.ru`, контейнеры `amola-*`, `/root/money_dock`) живёт на том же
  VPS — НЕ ТРОГАТЬ ВООБЩЕ** (прямой запрет владельца): никаких restart/rebuild/reload/правок
  `amola-*`, его Caddyfile, БД и файлов. Общий Caddy — контейнер `amola-web-1`; маршрут Perevozki
  в нём уже есть, свои передеплои Perevozki делай только в `/opt/perevozki` — Caddy при этом
  трогать не нужно. Если без Amola не обойтись — остановись и спроси владельца.
- Cement CRM на том же VPS (`/opt/cement-crm`, `cement-crm-*`) — тоже только чтение.
- **Не собирать Docker-образы на VPS** (`docker compose ... --build`). 2026-10-09 сборка
  backend+frontend Perevozki (2 vCPU, 4 ГБ, медленный диск, steal от хостинга) подвесила сервер
  примерно на 4–5 минут — Amola Finance был недоступен. Пока нет готовых образов из CI
  (AGENT_TODO P0), любой передеплой Perevozki на сервере — только с согласия владельца.
- Секреты — только через `.env` (в git не попадает). Новые переменные добавляй в
  `.env.example` (без значений) и в README («Окружение»). Репозиторий **публичный**: никаких
  токенов, паролей, ключей, дампов БД, IP/доступов VPS в коммитах.
- Необратимые действия (удаление данных/томов `docker volume rm`, правки прод-БД,
  `git reset --hard` по чужой работе) — только по явной команде владельца.

## Git-стратегия

- `main` — рабочая ветка, всегда в состоянии «собирается и проходит проверки».
- Значимые изменения — короткоживущими ветками **внутри этого репозитория**:
  `feature/<что>`, `fix/<что>`, затем merge в `main`. Лишних веток не плодить.
- Ветки других проектов (Cement CRM, SOVA, Amola и т.д.) не использовать никогда.
- Перед commit/push:

  ```bash
  git rev-parse --show-toplevel
  git branch --show-current
  git remote -v
  git status
  ```

## Подводные камни (уже наступали)

- **После `npm install` всегда `npm run db:generate`.** Prisma ищет схему в корне, не находит
  (она в `backend/prisma`) и генерирует клиент-заглушку — все типы Prisma становятся `any`,
  typecheck падает с `implicitly has an 'any' type`.
- **Вход локально** — только через `npm run dev:init-data` (подписанный тестовый initData).
  Обхода проверки подписи нет и не добавлять. Токен в `.env` и в скрипте должен совпадать;
  ID из `ADMIN_TELEGRAM_IDS` — владелец, любой другой (`--id 1001`) — зритель.
- **Роли:** зрителю открыто только то, что в `viewerRoutes` (`backend/src/equipment.ts`); всё
  остальное закрыто по умолчанию. Новый маршрут для зрителя — только осознанно, с тестом в `api.e2e.ts`.
- **Порты на машине владельца (Windows):** 5432 занят Postgres от другого проекта — у Perevozki
  `DB_PORT=5433`; backend dev — 3010, Vite — 5180, Docker-фронтенд — 8080.
- **`preview_start` в Claude Desktop** может читать `.claude/launch.json` другого проекта
  (той папки, из которой открыта сессия). Не правь чужой `launch.json` — запусти `npm run dev`
  фоном и открой `preview_start` с `url`.
- **Сеть машины владельца медленная** (npm/Docker Hub ~100 КБ/с): `npm install` и первая
  `docker compose build` занимают десятки минут — запускай в фоне. В Dockerfile уже есть
  кэш npm (`RUN --mount=type=cache`).
- **`api.telegram.org` с машины владельца недоступен** (ETIMEDOUT) — бота локально не проверить,
  только на VPS.
- **CRLF:** `core.autocrlf=true` на Windows; `.gitattributes` форсирует LF (важно для `.sh` и
  Dockerfile). Скрипты запускать через `sh scripts/...` (Git Bash).
- **e2e-тесты** пишут в БД из `DATABASE_URL`, но только свои записи с уникальными именами и
  удаляют их; лимитов и общих пользователей нет.
- **curl из Git Bash** портит кириллицу в `-d '{...}'` (кодировка консоли) — для ручных
  API-проверок с кириллицей используй браузер или Node.
