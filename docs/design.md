# Дизайн Perevozki — правила

Обновлено: 2026-10-19 · Claude Code (Windows). Стили — `frontend/src/styles.css`, компоненты —
`frontend/src/equipment/ui.tsx`. Любой новый экран собирается из них, а не из новых карточек.

## Задача владельца

«Красиво, удобно, понятно и без признаков вёрстки от ИИ». Признаки, которые раздражают людей
(по разборам [superdesign.dev](https://www.superdesign.dev/blog/why-ai-design-looks-generic),
[managed-code.com](https://www.managed-code.com/blog-post/ai-slop-in-design),
[uxdesign.cc](https://uxdesign.cc/how-to-de-slopify-your-designs-4c40c57c1dc9)):

| Не делаем | Вместо этого |
|---|---|
| Одинаковые карточки на каждую запись (свой бордер, радиус, тень) | Одна подложка `.ledger` на группу, строки через 1px-разделитель, даты — серые строки внутри (`.ledger-day`) |
| Полупрозрачный/тонированный фон + цветная обводка, «стекло», blur | Плотные цвета из токенов; тонированный фон — только у ошибки (`.error`) |
| Фиолетовые/синие градиенты, «свечение» | Палитра бумаги и чернил + лаймовый акцент только там, где он уже был (итоги аналитики) |
| Иконки в квадратиках, эмодзи вместо иконок | Иконки только функциональные (закрыть, назад); монограмму «П» из шапки убрали |
| Бейджи-«пилюли» на каждом шагу | Статус оплаты — цветной текст («Оплачено» / «Не отдали»), с пунктирным подчёркиванием, если нажимается |
| Разные тени у разных элементов | Тень одна — у шторки (`.sheet`); у остального теней нет |
| Скругление «на всё» одно и большое | `--radius: 12px` для подложек, `--radius-sm: 9px` для полей и кнопок |
| Нет состояний | Есть «Загружаем…», «Считаем…», пустые списки, ошибки внутри шторки, `disabled` у кнопок |
| `prompt()` / `confirm()` | Правка в нижней шторке; удаление в два касания («Точно удалить?») |

## Токены

`--paper` фон вокруг, `--page` фон страницы, `--surface` белые подложки, `--ink` / `--ink-2` /
`--ink-3` текст по важности, `--line` разделители, `--dark` основная кнопка и выбранный вариант,
`--ok` оплачено, `--debt` долг, `--danger` удаление. Шрифт — Manrope (его же использует блок,
который владелец просил сохранить). Суммы — `.money`: `tabular-nums`, жирные, без переноса,
по правому краю.

## Компоненты (`ui.tsx`)

- `Field` — подпись над полем; поля 46px, шрифт 16px (iOS не зумит).
- `Choice` — выбор кнопками (машина, категория, фильтр). Не «пилюли»: радиус 9px.
- `Row` — строка списка: слева заголовок + серая подпись (переносится), справа сумма и статус.
  Касание по левой части открывает правку.
- `DayGroup` — разделитель дня внутри подложки; сумма дня — только если записей больше одной.
- `Sheet` — нижняя шторка (правка, детализация аналитики), кнопка «Назад» для вложенных уровней.
- `PaidCheck` — зелёная галочка 34px справа в строке ходки (переключает оплату; удобнее пальцем,
  чем текст); `PaidStatus` — только текст под суммой.
- `DateChips` — «Сегодня / Вчера / Позавчера» + день последней добавленной записи (по id),
  подсвеченный сплошным лаймом; должны помещаться в одну строку на 375px.
- `DeleteButton`, `Empty`, `ErrorNote`, `MoreButton` (по 60 строк).

## Списки

- «Все машины»: блок на машину (имя + жирная линия-подчёркивание + итог), внутри — дни по
  убыванию, внутри дня — свежие сверху. Конкретная машина — только дни.
- Числа с телефона: запятая и пробелы допустимы (`toNumberInput`).

## Не трогать без владельца

Аналитика: плитки «Выручка / Расходы / Чистая прибыль / Не отдали» и карточки «По технике» —
владелец отметил, что они ему нравятся. Их CSS-правила в `styles.css` перенесены как есть и
помечены комментарием. Меняется только то, что открывается по нажатию.
