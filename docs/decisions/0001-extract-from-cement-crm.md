# ADR 0001 — Выделение раздела «Техника» из Cement CRM в самостоятельный проект

Дата: 2026-10-09 · Статус: принято · Автор: Claude Code (Windows)

## Контекст

В Cement CRM (`Serega000777/cement`, `agent/mvp-foundation@1f1779a`) есть рабочий раздел
«Техника»: машины, ходки, расходы, аналитика. Владелец хочет отдельное приложение Perevozki
со своим ботом, БД и деплоем, сохранив поведение раздела. Подробный разбор источника —
[`../cement-source-analysis.md`](../cement-source-analysis.md).

## Решения

1. **Стек как в источнике**: npm workspaces, Express 5 + Prisma 6 + PostgreSQL 16, React 19 +
   Vite 6, Telegraf 4, Docker Compose. *Альтернатива:* переписать на другой стек (NestJS,
   Next.js) — отклонено: перенос 1:1 без смены фреймворка снижает риск (M1 — parity).

2. **Имена таблиц сохранены** (`EquipmentVehicle`, `EquipmentTrip`,
   `EquipmentExpenseCategory`, `EquipmentExpense`). *Альтернатива:* переименовать в
   `Vehicle`/`Trip`/... — отложено до M2: одинаковые имена позволяют перенести
   прод-данные одним `pg_dump --data-only` (`scripts/import-from-cement.sh`).

3. **Новая init-миграция** вместо истории миграций Cement: БД Perevozki поднимается с нуля
   одной миграцией, сгенерированной из `schema.prisma` (+ сидинг 5 стандартных категорий,
   как в миграции источника). Цементные таблицы и FK не переносятся (их и не было у техники).

4. **Бот — отдельный сервис** `bot/` (в источнике жил внутри процесса API). API и бот
   масштабируются и перезапускаются независимо; API не нужен доступ к Telegram API.
   Long polling, как в источнике: не нужен входящий HTTPS для вебхука.

5. **Авторизация**: та же HMAC-проверка `initData` по `BOT_TOKEN` (срок 24 ч), вход только
   для `ADMIN_TELEGRAM_IDS` (список вместо одного `ADMIN_TELEGRAM_ID`). Обход `DEV_AUTH` из
   источника **удалён**: для локальной разработки `scripts/dev-init-data.mjs` подписывает
   тестовый initData тем же токеном, поэтому проверка подписи работает всегда.

6. **Один публичный порт**: nginx фронтенд-контейнера отдаёт SPA и проксирует `/api` и
   `/health` на backend (как в источнике). Внешний reverse proxy (Caddy) смотрит только на
   фронтенд — это совместимо со схемой «общий прокси на VPS» из `docker-compose.vps.yml`
   Cement.

7. **Миграции остаются в `backend/prisma/migrations`** (стандарт Prisma), а не в корневой
   папке `migrations/`: перенос папки ради структуры потребовал бы нестандартной настройки.

## Последствия

- Код Perevozki не ссылается на Cement CRM и собирается без него.
- Известные особенности источника (float в денежной арифметике, «сегодня» в UTC на
  фронтенде, правка через `prompt()`) сохранены осознанно и вынесены в M2/M3 (AGENT_TODO.md).
