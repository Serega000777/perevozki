# ADR 0003 — Роли: владелец и зритель

Дата: 2026-10-09 · Статус: принято · Автор: Claude Code (Windows)

## Контекст

Владелец хочет, чтобы правки вносил только он, а остальные пользователи бота видели только
статистику. До этого `ADMIN_TELEGRAM_IDS` был белым списком входа: всем остальным — 403.

## Решение (выбор владельца)

- **Владелец** — Telegram ID из `ADMIN_TELEGRAM_IDS`: всё как раньше (все вкладки, правки).
- **Зритель** — **любой** пользователь Telegram с валидной подписью initData: только вкладка
  «Аналитика», без переключения оплаты.
- `ADMIN_TELEGRAM_IDS` сохранил имя, но теперь означает «кто вносит правки», а не «кто входит».
- Права проверяет **сервер**: middleware в `equipmentRouter` пропускает зрителя только на
  `GET /analytics` и `GET /vehicles` (список машин нужен фильтру статистики), остальное — 403
  «Доступен только просмотр статистики». Новые маршруты закрыты для зрителя по умолчанию.
- `/api/auth/me` отдаёт `role`; фронтенд по ней показывает зрителю только аналитику и не
  запрашивает ходки/расходы/категории.

## Альтернативы

- **Зрители по списку ID** — безопаснее (цифры бизнеса не видит случайный человек, нашедший
  бота), но владелец выбрал открытый просмотр. Переключить легко: добавить список зрителей и
  отказывать остальным в `telegramAuth`.
- **Скрывать кнопки только во фронтенде** — отклонено: API остался бы открыт для правок.
- **Журнал изменений / дата обновления для зрителя** — владелец отказался.

## Последствия

- Статистику (выручка, расходы, долги, строки ходок в детализации) видит любой, кто откроет бота.
- В таблицу `User` попадает каждый, кто открывал Mini App (имя и Telegram ID), как и раньше.
